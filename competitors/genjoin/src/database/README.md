# FAQ

## PostgreSQL issues

### How to restore PostgreSQL database?

#### From `*.sql` file
By executing the sql files found on [Google Drive](https://drive.google.com/drive/folders/1RSJWYPqfRm4_WuAJc2q124NI1DzA5N6V?usp=sharing) sql dump the exact same databases are
reconstructed which were used for the thesis "Machine Learning-Based Query Optimization". The script was gnereated by executing
`pg_dump` for the respective databases and thus do not only contain the data but also
reconstruct the schema.

1. At first you need to run `docker-compose -f docker-compose-gqml.yml up --detach` as it contains Postgres datatbase as a service (all the credentials are in `.env`)
2. Then get file e.g. `shop_db_non_uniform.sql` and run the following (more explanations on how to run `.sql` file within Docker could be found [here](https://stackoverflow.com/questions/34688465/how-do-i-run-a-sql-file-of-inserts-through-docker-run):
    - `docker cp ./postgresql/sql/shop_db_non_uniform.sql gqml_postgres:/docker-entrypoint-initdb.d/shop_db_non_uniform.sql` (DEPRECATED, has been added to *.yml)
    - `docker exec -it -u postgres gqml_postgres psql postgres --command 'CREATE DATABASE shop_db_non_uniform TEMPLATE template1;'`
    - `docker exec -u postgres gqml_postgres psql shop_db_non_uniform postgres -f docker-entrypoint-initdb.d/shop_db_non_uniform.sql`

#### From `*.dump` file
If the dump has been generated by `pg_dump -Fc`, then you need to use `pg_restore` command. Key steps remain the same as from previous way of database restoring:
1. Create database e.g. `CREATE DATABASE imdb`
2. Copy your `*.dump` file into Docker container (usually into folder `docker-entrypoint-initdb.d`) 
3. Run inside the Docker bash: `pg_restore -d imdb -U postgres --verbose /docker-entrypoint-initdb.d/imdb.dump`
4. Try that everything works by running some query via: `docker exec -it -u postgres gqml_postgres psql imdb postgres --command "<YOUR_SQL_QUERY>"`

### How to 'dive' inside the Docker container and PostgreSQL in it?
You can connect to command line of the container in run via the command: `docker exec -it gqml_postgres bash`

There being on `localhost` you can simply go into Postgres with `psql -U postgres` and call the commands:
 - `\list` or `\l`: list all databases
 - `\c <DB_NAME>`: connect to a certain database
 - `\dt`: list all relations (tables) in the current database
 - `\d <TABLE_NAME>`: access schema of a given table
 
### How to set the limits for statistics like `most_common_vals` and `histogram_bounds`?
The amount of information stored in pg_statistic by `ANALYZE`, in particular the maximum number of entries in the `most_common_vals` and `histogram_bounds` arrays for each column, can be set on a column-by-column basis using the `ALTER TABLE` command (e.g. `ALTER TABLE aka_title ALTER movie_id SET STATISTICS 10`, or globally by setting the `default_statistics_target` configuration variable via `ALTER DATABASE imdb SET default_statistics_target=30` command. The default limit is presently 100 entries.

_NB!_ [default_statistics_target](https://www.postgresql.org/docs/13/runtime-config-query.html#GUC-DEFAULT-STATISTICS-TARGET) will not overwrite the value for the cases where you have set it via [ALTER TABLE](https://www.postgresql.org/docs/13/sql-altertable.html) method.

### Why do I get error `Error response from daemon: Error processing tar file(exit status 1): unlinkat /docker-entrypoint-initdb.d/<FILENAME>: device or resource busy` when trying to copy file into container?
The point is that some process is using your file/folder. There're several possible solutions:
1. Get with command `lsof +D <NAME>` and then use `kill -9 <PID>` all the process ids (keep in mind that one of the processes might occur to be your running bash console)
2. If it does not help, install some editor like `apk update` and `apk add nano`, and check - perhaps all the stuff has been copied despite the error (was my case)
3. If still does not help, then using editor try to make the changes you've intended to do

### Why sometimes when calculating funcitonal dependencies via `CREATE_STATISTICS` I get small value like "1 => 2: 0.00011", and in next run it disappears from output?
It happens in case functional dependency between columns is very small, and as with running `ANALYZE` after creation of statistics every time you're making samples from table, in some cases dependency is greater than 0.0001 and shown in results, otherwise not (threshold value has been figured out empirically through sample runs).

### What if I have a problem with PostgreSQL processes, e.g. running a query does not finish, or some unknown process is making work slow?
In order to find out what processes are using your PostgreSQL database (like side processes, or unfinished queries), you can get them via the query:
```
SELECT pid, age(clock_timestamp(), query_start), usename, query
FROM pg_stat_activity
WHERE query != '<IDLE>' AND query NOT ILIKE '%pg_stat_activity%'
ORDER BY query_start desc;
```
There you'll find out for how long the processes are running, and then in order to cancel the long running queries you should execute: `SELECT pg_cancel_backend(__pid__);`
If the you find the process is stuck you can kill it by running: `SELECT pg_terminate_backend(__pid__);`

_NB!_ `pg_terminate_backend` is the `kill -9` in PostgreSQL. It will terminate the entire process which can lead to a full database restart in order to recover consistency.

### How to edit the PostgreSQL configuration parameters and create your own?

You can make all manipulations with parameters inside the current Postgres session, however you can also edit the parameters "forever", and also add your own to the configuration file. You can find the file by searching from the root directory `find . -name "postgresql.conf"`, and then add/edit whatever you need.

_NB!_ Don't forget to [reload config](https://stackoverflow.com/questions/71309715/how-to-reload-postgresql-configuration) after editing it!

## Psycopg2 issues

### Why do I get `KeyError` when processing e.g. JOB queries having LIKE condition?
This happens if you're using a prepared statement, as in this case the input will be wrapped in '' to prevent sql injection.
In order to overcome that issue, you need to escape % by using %% in the LIKE operand, i.e. `k.keyword LIKE '%%sequel%%'` instead of original `k.keyword LIKE '%sequel%'`

## PgCuckoo

### Installation
Follow the instructions from the [official PgCuckoo project](https://github.com/kryonix/pg_cuckoo/tree/master/PgExtension#Installation), mind the key points below:
 - case there're issues with something like `llvm` - install all the additional packages required, connected to compilation of C code
 - after the installation process, don't forget to run the `cuckoo--1.0.sql` in order to get the correct initialization of functions 

### When trying to create extension, it says that only superuser can do this

Check with `psql` the roles existing with the command `\du` - and e.g. if the superuser role is assigned to `postresql_sys`, then you can alter the role of the postgres user by running: `docker exec -it -u postgres gqml_postgres psql imdb postgresql_sys --command "ALTER ROLE postgres SUPERUSER"`. After that, you can go into `psql` and drop all "fake" users, like `DROP USER odoo_sys, odoo_user, postgresql_sys`.

## pg_hint_plan

This plan hinter is supported since 2012, could be easily installed from [here](https://github.com/ossc-db/pg_hint_plan/blob/master/README.md#installation).

You might need to first make the following installations (inside the Docker as well):

```
apt-get update
apt-get install zip
apt-get install make
apt-get install gcc
apt-get install postgresql-server-dev-14
```

The last installation should be done in case you encounter issue with `postgres.h` (please find original source [here](https://stackoverflow.com/questions/56724622/how-to-fix-postgres-h-file-not-found-problem)). Case still having problems after installation, try `CREATE EXTENSION pg_hint_plan;` as it should already explicitly create an extension inside Postgres.

It is quite simple in use - please see the example below with hash join selected as the joning method and `pgbench_accounts` scanned by sequential scan method:

<pre>
postgres=# /*+
postgres*#    <b>HashJoin(a b)</b>
postgres*#    <b>SeqScan(a)</b>
postgres*#  */
postgres-# EXPLAIN SELECT *
postgres-#    FROM pgbench_branches b
postgres-#    JOIN pgbench_accounts a ON b.bid = a.bid
postgres-#   ORDER BY a.aid;
                                        QUERY PLAN
---------------------------------------------------------------------------------------
    Sort  (cost=31465.84..31715.84 rows=100000 width=197)
    Sort Key: a.aid
    ->  <b>Hash Join</b>  (cost=1.02..4016.02 rows=100000 width=197)
            Hash Cond: (a.bid = b.bid)
            ->  <b>Seq Scan on pgbench_accounts a</b>  (cost=0.00..2640.00 rows=100000 width=97)
            ->  Hash  (cost=1.01..1.01 rows=1 width=100)
                ->  Seq Scan on pgbench_branches b  (cost=0.00..1.01 rows=1 width=100)
(7 rows)

postgres=#
</pre>

_NB!_ Before use make sure that you've loaded the hinter with `LOAD 'pg_hint_plan';` and have `SET pg_hint_plan.enable_hint_tables TO off` (or just include it into `postgresql.conf` file) case you don't want to use customized [hint tables](https://github.com/ossc-db/pg_hint_plan/blob/master/README.md#the-hint-table). Also I'd highly recommend to first [initialize toy database](https://github.com/ossc-db/pg_hint_plan/blob/cde640fdefad9b0d6cc50985fdf93eb50bf01903/sql/init.sql) and [run sample SQL](https://github.com/ossc-db/pg_hint_plan/blob/cde640fdefad9b0d6cc50985fdf93eb50bf01903/sql/pg_hint_plan.sql) to see how the hinter works with different hints and parameters setteled.
